# Scribiva v1.0 — 架构决策记录（ADR）与风险台账

## ADR-001：桌面优先，而非浏览器插件

- **状态**：Accepted
- **原因**：用户明确要求跨应用，浏览器内输入不能满足核心定位。
- **决策**：Tauri 2 + Rust 系统适配器；Windows/Linux 双平台。
- **代价**：权限与兼容性复杂度增加。

## ADR-002：Linux 输入参考 Voxtype 的多驱动策略

- **状态**：Accepted as reference; implementation pending PoC
- **原因**：单一输入后端不可能覆盖 X11、GNOME/KDE Wayland 与 wlroots 环境。
- **决策**：参考 `wtype/eitype/dotool/ydotool/clipboard/xclip`，使用平台能力检测和可诊断回退。
- **代价**：后端测试矩阵大；需权限审查和许可证管理。
- **反对方案**：强制所有用户启用 uinput 或加入 `input` 组；因权限过宽而放弃。

## ADR-003：云端多语言 ASR，端侧模型后移

- **状态**：Accepted for MVP
- **原因**：20 语言上线、低设备依赖以及部署速度优先。
- **决策**：先用可替换的云 ASR 适配器，优先验证 Whisper 多语言模型；离线 v1.1+ 再评估。
- **代价**：需要网络、供应商费用和云端数据处理透明度。

## ADR-004：语法修正独立于 ASR

- **状态**：Accepted
- **原因**：语法质量、成本和回退需要独立控制。
- **决策**：`raw | standard | polished`（界面标签：原文 / 智能修正 / 流畅表达），默认 standard；LLM 失败回原文；保护结构/事实。
- **代价**：增加额外 API 延迟及成本。

## ADR-005：单次输入不保证外部可验证

- **状态**：Accepted
- **原因**：跨进程键盘事件通常缺乏目标编辑器确认写入的标准反馈。
- **决策**：显示 `dispatched_unverified`，对不确定结果停止自动重试并提供复制/确认。
- **代价**：UI 文案更复杂，但避免重复粘贴。

## ADR-006：Obsidian 双模式为 P0

- **状态**：Accepted
- **原因**：用户明确要求；且 Markdown/撤销是兼容性最容易出问题的场景。
- **决策**：Live Preview、Source Mode 与 Reading View 降级分别测试。
- **代价**：需要真实应用测试环境，不是单测能替代。

## ADR-007：最小化敏感数据保留

- **状态**：Accepted as design baseline, subject to legal/security review
- **原因**：音频、转写与剪贴板可能包含高敏感内容。
- **决策**：不默认永久保留音频和正文，服务器短 TTL，数据最小化，诊断 opt-in。
- **代价**：历史追溯和离线重试能力受限。

## ADR-008：Linux 先行开发，Windows 与 Linux 同时首发

- **状态**：Accepted（2026-10-28，PD-02/PD-03）
- **原因**：现有可运行实现与已验证的输入路径都在 Linux；同时要求 Windows 不推迟到 v1.1。
- **决策**：每个 Gate 的平台项先在 Linux 通过，Windows 按同一 P0 标准完成后 Gate 才关闭；v1.0 两个平台同日发布。
- **代价**：发布日期取两个平台中较晚者；Windows 适配和真机 QA 不能被 Linux 进度掩盖。

## ADR-009：每月免费层 + 订阅；Stripe 为主，Paddle 待评估

- **状态**：Accepted（Stripe、每月免费层）；Paddle 为 Proposed（2026-10-28，PD-04/PD-05）
- **原因**：每月免费层便于持续获客与口碑；Stripe 集成已有服务端骨架；Paddle 作为 MoR 可代缴税并支持人民币支付宝订阅。
- **决策**：服务端按自然月重置免费额度；订阅结束降回免费层；支付通道经适配层接入，权益只认验签订阅事件。Paddle 按 PRD §11.3 标准在 G2 前评估。
- **代价**：免费层持续产生供应商成本，需要滥用控制（R7）；双通道并存会增加 webhook 映射与对账复杂度。

## ADR-010：Groq + 美国服务端，所有地区统一接入

- **状态**：Accepted（2026-10-28，PD-07/PD-08）
- **原因**：继续使用已集成的 Groq；单一美国部署可以降低运维和合规面的复杂度。
- **决策**：客户端（含中国大陆用户）只连接 Scribiva 美国服务端，由服务端调用 Groq；Groq 密钥只在服务端。收款使用现有 Stripe 账户。供应商适配层保留，但 v1.0 不做按区域路由。
- **代价**：大陆用户承受跨境延迟与网络干扰风险；语音与文本出境需告知与合规确认；Groq 故障时没有备用供应商。

## ADR-011：v1.0 服务端沿用 Python + SQLite 单实例

- **状态**：Accepted（2026-10-28，关闭 D-006）
- **原因**：`server/scribiva_server/` 已实现鉴权、额度预留、幂等、取消/过期、限流、Stripe 验签与隐私删除，并有离线测试覆盖。$1,000 MRR 约对应 125 个付费账户加免费层，单台美国服务器足以承载；改写为 Node/Fastify 或 Rust 不产生用户可见价值。
- **决策**：v1.0 服务端使用 Python 3.12 + SQLite（WAL），单实例部署在美国服务器，前置反向代理终止 TLS 并限制请求体与超时；数据库做定时备份与恢复演练。依赖保持最少，新增第三方依赖需固定版本并经评审。
- **迁移触发条件**：需要多实例、跨区域部署，或写入并发成为瓶颈时，再迁移到 PostgreSQL 与共享限流；`DictationService` 与 `db.py` 的边界保持可替换。
- **代价**：单点故障，需要监控与快速恢复手册；限流和任务状态在单进程内。

## ADR-012：焦点校验——平台扩展优先，无法校验时默认只复制

- **状态**：Accepted（2026-10-28）
- **原因**：GNOME Wayland 不向普通应用提供焦点窗口信息，而“对未验证焦点自动粘贴”是发布阻断项（`07-SECURITY-PRIVACY.md` §8）。
- **决策**：
  1. **GNOME Wayland**：提供 Scribiva GNOME Shell 扩展，通过会话 D-Bus 只暴露当前焦点窗口的应用 ID、窗口 ID 和录音状态指示（顶栏图标，兼作不抢焦点的录音提示）；不暴露窗口标题和内容。
  2. **KDE Plasma Wayland**：用 KWin 脚本提供同等信息。
  3. **X11 / Windows**：用系统 API 读取前台窗口。
  4. 拿不到焦点信息时默认只复制；用户可在设置中明确开启“未校验也自动插入”，并看到风险说明。
  5. **Obsidian 可选插件**（P1）：在编辑器内直接插入，可返回 `verified`，撤销一步完成，不经过剪贴板。基线体验不依赖插件。
- **代价**：GNOME 扩展需随 GNOME 大版本适配并发布到 extensions.gnome.org；KWin 脚本同理；用户需要额外安装一步。

| R19 | GNOME Shell 扩展随 GNOME 大版本失效 | 中高 | 高 | 每个 GNOME 版本发布前回归；失效时自动降级为只复制并提示 |
| R20 | 单实例服务器故障或数据库损坏 | 低到中 | 严重 | 定时备份与恢复演练；健康检查与告警；恢复手册（`10-RELEASE-OPERATIONS.md`） |
| R21 | Whisper 在静音/噪声上产生虚构文字并被插入 | 高 | 中高 | FR-017 过滤；可疑结果不自动插入 |
| R14 | 部分大陆用户无法用 Stripe Checkout 完成订阅付款 | 中 | 中 | v1.0 接受该风险，不做专项处理；按实际转化数据再决定 |
| R15 | 支付平台网站审核未通过导致无法收费 | 中 | 高 | landing page 在 G2 前上线并覆盖 Stripe/Paddle 审核所需内容 |
