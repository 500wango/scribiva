# Scribiva v1.0 — 产品需求文档（PRD）

**状态**：Draft for implementation ｜ **负责人**：待指定 ｜ **更新**：2026-10-28（并入产品决策 PD-01～PD-08，见 §1.1；并入评审建议：FR-016～FR-019、焦点策略 ADR-012）

## 1. 背景与机会

Scribiva 进入已有付费需求的 AI 语音输入市场，不以自主训练 ASR 基础模型为差异化。产品竞争重点是 **全局跨应用的可靠输入、多语言质量、自动语法修正，以及 Windows/Linux 的真实兼容体验**。

**战略约束**：达到 $1,000 MRR，而非为了完成全部竞品功能牺牲可靠性。长期收入不等同于短期现金收入，终身版不在 v1.0。

### 1.1 已确认的产品决策（2026-10-28）

| ID | 决策 | 对需求的影响 |

| PD-04 | 商业模式为**每月免费层 + 订阅**，不采用一次性免费试用 | FR-010、US-005、首次启动流程按月度额度描述 |

“Linux 先行”与“同时首发”不冲突：前者约束**开发与验证顺序**，后者约束**对外发布**。任何 Gate 都不能以“Linux 已通过”为由跳过 Windows 的同级验收。

## 2. 北极星与可量化目标

- **北极星指标**：每周完成 ≥3 次听写的活跃账户数。“完成”以服务端 `completed` 作业计，不依赖客户端遥测同意；多数 Wayland 环境的插入结果只能是 `dispatched_unverified`，因此插入结果作为辅助指标（以不含内容的枚举随下一次请求上报，并在隐私说明中披露）。
- **商业目标**：达到 **$1,000 MRR**（定义见 `11-METRICS-ECONOMICS.md`）。
- **P0 产品成功条件**：核心语音链路在 Windows 与 Linux 受支持环境可用、Obsidian 通过专项测试、至少 20 种语言通过测试、订阅与每月免费额度由服务端有效执行、landing page 上线、中国大陆用户可完成“访问官网 → 下载 → 注册 → 听写 → 升级”全流程（付款方式以 §11 评估结论为准）。
- **早期验证门槛（建议，非行业基准）**：30 名定向用户参加测试、至少 5 个真实付费账户、核心应用测试成功率 ≥95%（G2 Beta 门槛；G3 正式门槛为 NFR-002 的 ≥99%）、无 P0 数据丢失或隐私事故。Beta 先从 Linux 用户招募，结束前须包含 Windows 用户与中国大陆用户，并分组统计。样本量不足以证明长期 PMF。

## 3. ICP 与用户任务

| 人群 | JTBD（待完成的任务） | 典型场景 | 用户付费理由 |
|---|---|---|---|
| 长时间写作者/知识工作者 | 少打字、快速写草稿 | Obsidian、Word、邮件 | 降低输入成本 |

## 4. P0 需求与验收（需求 ID 不可复用）

| ID | 用户需求 | 完成定义 |
|---|---|---|
| FR-001 | 全局快捷键触发 | 应用退到后台、目标软件有焦点时可启动/停止；冲突提示；Wayland 依环境提供引导与回退。P0 交互为**按一次开始、再按一次停止**；按住说话为 P1，仅在平台能提供按键释放事件时提供（GNOME 自定义快捷键只有按下事件） |
| FR-002 | 录音状态清晰 | 开始、录音中、处理、插入、错误、取消均有可感知反馈；不偷偷录音 |
| FR-003 | 多语言 ASR | 提供 20 种明确列出的语言；自动检测及手动指定；转写保持原语言，默认不翻译；中文简/繁输出由确定性转换保证，不依赖模型自行选择字形 |
| FR-004 | 语法修正 | 原文/智能修正/流畅表达三档；默认智能；保留本次原始转写供恢复 |
| FR-005 | 跨应用文本插入 | **停止录音时**记录目标窗口快照，注入前再次比对，一致才自动插入，否则转为预览 + 复制（详见 §7.3）；P0 校验粒度为窗口级（应用 + 窗口），编辑区级为 P1；终端类窗口默认只复制不粘贴；失败保留可复制文本；不自动发送 |
| FR-006 | Obsidian | Windows/Linux 目标环境：Live Preview / Source Mode、Markdown、换行、撤销通过 QA |
| FR-007 | 文字保护 | **确定性保护（P0）**：代码块、命令、文件路径、URL、邮箱、Markdown 结构在 LLM 前后逐字一致，校验失败回退原文；数字要求**数值不变**，允许“三点半 → 3:30”这类书面化格式变化。**专有名词**通过个人词典（FR-018）保护，以 QA 的“实体误改率”衡量 |
| FR-008 | 取消、超时、重试 | 取消录音不上传；超时/网络失败重试有界；避免双重插入 |
| FR-009 | 用户配置 | 快捷键、语言、模式、麦克风、插入策略、隐私设置可配置 |
| FR-010 | 商业化 | **每月免费层**：额度为服务端配置、按自然月重置，重置时间按用户本地时区展示；额度展示；订阅（月付/年付）；支付成功后权益由服务端同步；到期/欠费降回免费层而非停用账户；支付通道经适配层接入，首发 Stripe，可追加 Paddle 而不改动权益模型 |
| FR-011 | 隐私与安全 | 清晰云端处理告知（处理地区：美国；Groq 为语音与文本处理方；对中国大陆用户明示数据出境）；服务端持有 API 密钥；最小权限、日志脱敏、数据删除；中国大陆用户的数据出境告知与同意方式经法务确认 |
| FR-012 | 安装更新 | Windows 签名安装包与 Linux 受测安装包**同时**提供；可验证更新签名与回滚方案 |
| FR-013 | 可访问性 | 设置页键盘可操作；字幕/提示不依赖纯颜色；错误消息可复制 |
| FR-014 | Landing page | 首发前上线，至少包含：产品说明与核心功能、价格页（免费层额度、月付/年付价格与币种）、Windows/Linux 下载入口与校验值、公开兼容列表与已知限制、隐私政策、服务条款（含经营主体名称）、退款/取消政策、联系方式；HTTPS；简体中文与英文；中国大陆与海外均可访问；文案遵守 `06-UX-SPEC.md` §10 |
| FR-015 | 中国大陆可用性 | 在中国大陆网络环境（不使用代理）下，landing page、下载、账户、听写 API 与支付流程可用或有明确说明；客户端只连接 Scribiva 美国服务端，不直连 Groq 或其他境外模型接口；数据出境与服务形态满足法务确认的合规要求；客户端与 landing page 不依赖大陆不可访问的第三方资源 |
| FR-016 | 口述格式命令 | 识别“换行”“新段落”“列表项”等口述命令（中英文各一套），由**确定性规则**转换为换行、空行与 Markdown 列表，不交给 LLM 生成结构；命令词可在设置中关闭；支撑 US-002 |
| FR-017 | ASR 幻觉过滤 | 对静音或噪声段产生的虚构文字（如“谢谢观看”“字幕由 Amara.org 社区提供”）进行过滤：VAD 裁剪首尾静音、按 `no_speech_prob` / `avg_logprob` 设阈值、维护已知幻觉短语表；判为可疑的结果只进入恢复区，不自动插入 |
| FR-018 | 个人词典 | 用户可维护术语表（人名、产品名、代码标识符）；术语用于 ASR 提示词与 LLM 修正保护；在自动检测语言时同样生效；随账户保存在服务端，可导出与删除 |
| FR-019 | 账户注册与登录 | 邮箱魔法链接注册/登录；桌面端通过浏览器完成登录后回到应用（设备授权流程），不在桌面端输入密码；免费层按账户发放；同一邮箱不重复发放免费额度 |

**支持声明**：FR-005 的“跨应用”指公开兼容列表内的普通用户权限应用，不保证管理员权限窗口、密码框、锁屏、反作弊环境、远程桌面或所有 Wayland 合成器。FR-006 优先级高于“所有应用都支持”的泛化营销承诺。

FR-014 所列的价格、联系方式、退款、隐私和条款内容，同时是 Stripe 账户激活与 Paddle 域名审核的前置材料，因此 landing page 必须早于真实收费上线。

## 5. 首发 20 种语言（每种都需验收）

英语 `en`、中文普通话 `zh`、日语 `ja`、韩语 `ko`、西班牙语 `es`、法语 `fr`、德语 `de`、葡萄牙语 `pt`、意大利语 `it`、俄语 `ru`、阿拉伯语 `ar`、印地语 `hi`、土耳其语 `tr`、荷兰语 `nl`、波兰语 `pl`、印尼语 `id`、越南语 `vi`、泰语 `th`、瑞典语 `sv`、乌克兰语 `uk`。

- 自动检测用于通常单语音频；一句中多语言混说是单独质量测试项，不承诺对所有组合都达到相同准确度。
- 面向中国大陆市场，**中英混说**列为必测质量项，测试集需覆盖技术术语、产品名和代码标识符夹在中文中的情形。
- 中文提供简体/繁体**输出偏好**，不重复计为两种语音语言。
- 语法修正模块需提供上述语言的支持；某语言未通过修正验收时不能宣传“完整支持”。

## 6. 核心用户故事

### US-001 快捷键听写
**Given** 已安装并授予麦克风权限，且处于支持的输入区；**When** 用户按下全局快捷键、说话、结束；**Then** 显示进行状态，完成转写和所选 AI 处理，尝试向目标光标位置插入；失败保留文本并允许复制。

### US-002 Obsidian 编辑
**Given** Obsidian 处于 Live Preview 或 Source Mode；**When** 用户口述一条含中英文、换行、Markdown 列表的笔记；**Then** 内容只插入在指定位置、不重写其他笔记区、不自动触发笔记外操作、可撤销。

### US-003 语法修正
**Given** 选中“智能修正”；**When** ASR 返回口语文本；**Then** 自动补标点、修正明确的语法错误与口头禅，保留原意、日期、数字、实体；若改写失败返回原始转写且通知用户。

### US-004 多语言
**Given** 选择日语或自动检测；**When** 用户说日语；**Then** 转写为日语而非翻译为英文，并按所选模式处理。

### US-005 每月免费额度与付费
**Given** 免费层用户本月额度接近上限；**When** 用户访问设置或尝试下一次录音；**Then** 明示本月剩余时长、下次重置时间（本地时区）与付费方案；升级成功后服务端权益状态生效，客户端缓存不能成为权限真相来源；订阅结束后账户回到免费层。

### US-006 Landing page 转化
**Given** 访客从搜索、社区或推荐链接进入 landing page；**When** 浏览产品介绍、价格与兼容列表；**Then** 能按自己的平台下载正确安装包，看到免费层额度、付费价格、隐私与退款政策，页面不出现超出 QA 结论的支持承诺。

### US-007 中国大陆用户
**Given** 用户位于中国大陆且未使用代理；**When** 访问 landing page、安装、注册、听写并尝试升级；**Then** 每一步可用或给出明确说明；听写延迟按大陆测试网络单独统计；可用的付款方式以已开通的支付通道为准并在价格页说明。

## 7. 交互流程与边界

1. 首次启动：隐私说明（含处理地区）→ 注册/登录（FR-019）→ 麦克风授权 → 检测系统会话/输入后端（GNOME 扩展 / KWin 脚本引导）→ 快捷键绑定 → 示例测试 → 显示本月免费额度。
2. 主流程：空闲 → 录音 → 处理 → 结果可恢复 → 注入尝试 → 完成/失败；不自动发送、提交或执行命令。
3. 目标焦点：**停止录音时记录目标窗口快照，注入前再次比对**；处理期间用户切换窗口则暂停自动插入并请求确认/手动复制，不盲目向新焦点输入。无法取得焦点信息的环境（例如未安装 GNOME Shell 扩展的 GNOME Wayland）默认只复制，自动插入需用户在设置中明确开启并看到风险说明（ADR-012）。
4. 权限缺失：说明原因，给出最小权限操作与撤回办法；不得以 root 运行完整客户端。
5. 文本恢复：最近一次转写在本地短期保留（默认至应用退出，用户可立刻清除）；音频默认处理后删除，不默认保留原录音。
6. 获客路径：landing page → 下载 → 首次启动 → 注册/登录 → 免费层使用 → 额度不足时进入价格页或结账。
7. 额度边界：开始录音时显示本月剩余额度；若本段录音超出剩余额度，本段仍完整处理并扣至 0（每月最多一段，宽限上限由服务端配置），之后的录音在开始前即提示升级，不让用户录完才被拒绝。

## 8. 非功能需求（初始工程目标，须用实测校准）

- NFR-001：短录音（≤15 秒）结束后至结果就绪的 P95 目标 ≤3 秒，在已定义测试网络和设备下测量；非 SLA。中国大陆测试网络单独定基线与报告，不与海外数据合并。
- NFR-002：受测平台/应用矩阵的正确插入率目标 ≥99%；不能观测写入结果时单独报告 `dispatched_unverified`，不得计为验证成功。
- NFR-003：取消后不能发生 ASR 上传或文字插入；若请求已经发出，应避免继续处理及应用结果。
- NFR-004：无音频流或文本正文进入常规分析日志；故障遥测采用显式同意。
- NFR-005：断网时清晰提示，不阻塞操作系统输入法；错误路径不丢失已得到的转写结果。
- NFR-006：至少支持屏幕阅读器可识别的设置表单与状态文字。
- NFR-007：由用户明确启动录音，录音条可见；不存在后台持续监听业务音频的路径。
- NFR-008：landing page 在中国大陆与海外的首屏可用（具体加载指标在 G2 前用实测定基线）；不依赖大陆不可访问的字体、脚本或统计服务。

## 9. 不做的范围（v1.0）

macOS、移动端、离线 ASR、会议机器人、团队管理、跨设备文本同步、自训练模型、无限制免费使用、一次性免费试用（由每月免费层替代）、自动邮件发送、终身买断、对任何 Linux 组合器的普遍兼容保证。

## 10. 产品发布 Gate

每个 Gate 的平台项均先在 Linux 上通过（PD-02），Windows 按同一标准完成后该 Gate 才算关闭（PD-03）。

- **G0 技术可行**：Linux（GNOME/KDE Wayland 及选定的 X11 环境）与 Windows 的目标组合完成输入原型，或明确缩小平台支持范围。Windows 不允许以缩小范围的方式移出 v1.0。
- **G1 Alpha**：20 语言最基本识别测试、核心链路、Obsidian 与恢复流程在 Linux 上稳定；Windows 核心链路可运行。完成中国大陆网络到美国服务端的可达性与延迟实测，以及合规初评（§11.2）。
- **G2 Beta**：真实用户（先 Linux，后加入 Windows 与中国大陆用户）、Stripe 订阅沙箱与生产链路、隐私说明、兼容列表、自动更新完成；**landing page 上线**并通过 Stripe 账户激活所需的网站审核；Paddle 评估得出结论（§11.3）。
- **G3 正式**：`08-QA-ACCEPTANCE.md` 所列全部 P0 在 Windows 与 Linux **均**通过后同时发布；发布说明逐项列出已支持 Windows 版本、Linux 会话与已知限制；landing page 的价格、兼容列表与 QA 结论一致。

## 11. 主要依赖和未决项

### 11.1 决策待定

- 默认首版定价（建议测试 $8/月与 $69/年，非已批准价格）；人民币定价是否单独设置。
- 每月免费层额度（服务端骨架当前默认 1,800 秒/月，仅为工程默认值，未经批准）。
- 哪种 Linux 安装方式先正式支持；Windows 最低版本（D-001）。
- landing page 与服务端的域名方案（托管已定为美国，见 PD-07）；需实测大陆访问质量。

### 11.2 中国大陆市场的前置风险（G1 前完成初评）

**已定架构（PD-07）**：客户端 → Scribiva 美国服务端 → Groq。Groq 调用全部发生在美国服务器之间，大陆用户的网络只需要能到达 Scribiva 服务端。开发期在本机直连 Groq 时出现过 Cloudflare 1010，部署后需在美国服务器上重新验证，不能沿用本机结论。

- **网络可达性与延迟**：landing page、下载、账户、听写 API、更新服务在大陆网络（无代理）下实测，记录丢包、跨境 RTT 与上传耗时；域名或 IP 被干扰时要有可切换的备用域名方案。
- **上传体积**：跨境上行带宽不稳定，WAV 上传可能占据大部分延迟。建议客户端上传前压缩为 FLAC 或 Opus（服务端已支持经 `ffprobe` 校验非 WAV 格式），以实测结果决定。
- **合规**：面向大陆公众提供生成式 AI 服务可能涉及算法/生成式 AI 备案；语音与文本传往美国处理涉及个人信息出境规则。须法务确认后决定大陆的上线形态（例如是否公开推广、告知与同意方式），不能以“技术上能访问”代替合规结论。服务器和官网均在境外托管，不涉及境内 ICP 备案。
- **第三方资源**：客户端与 landing page 不得依赖大陆不可访问的 CDN、字体、验证码或统计脚本。

### 11.3 支付通道：Stripe 为主，Paddle 为第二选项

**首发方案**：Stripe Checkout + Billing Portal + 验签 Webhook（服务端骨架已实现）。权益模型与支付通道解耦：服务端只认“已验签的订阅事件 → 本地订阅状态”，以便追加 Paddle 时不改动额度与权益逻辑。

**已知约束（2026-10-28 查阅，上线前复核）**：

- 使用现有 Stripe 账户（PD-08）。v1.0 不针对中国大陆单独开通或评估本地支付方式，付款方式以 Stripe Checkout 实际展示为准。
- Paddle 作为 Merchant of Record 代收代缴全球销售税，费率约 5% + $0.50/笔；支付宝订阅仅对以人民币定价、账单地址在中国的客户开放，需 Paddle 额外审批，单次续费上限 1,600 CNY；微信支付仅支持一次性购买。

**Paddle 评估标准（G2 前得出结论）**：

| 维度 | 评估问题 |
|---|---|
| 大陆用户付款 | 支付宝订阅能否开通、实际成功率；与 Stripe 银行卡路径对比 |
| 税务与合规 | MoR 代缴能否显著降低多地区销售税负担；与 Stripe Tax 自行申报的成本对比 |
| 综合费率 | 在 $8/月 价位下每笔净收入（含汇率、退款、争议） |
| 主体资格 | 现有 Stripe 账户的经营主体能否同时开通 Paddle |
| 工程成本 | Webhook 映射、退款/争议事件、账户迁移与双通道并存的复杂度 |

评估结论记录为 ADR。若采用 Paddle，可以作为大陆用户的支付通道与 Stripe 并存，也可以取代 Stripe；两种情况都必须先通过 Paddle 域名审核，而该审核同样依赖 FR-014 的 landing page 内容。

### 11.4 需原型验证

GNOME Shell 扩展 / KWin 脚本提供焦点窗口信息的可行性与维护成本（ADR-012）；Obsidian 插件 `verified` 插入路径；GNOME/KDE Wayland Portal 的实际权限和性能；中文 Unicode 与 Markdown 粘贴/撤销表现；Windows 下 Obsidian 两种编辑模式的注入与撤销。

### 11.5 需法务/商务确认

Groq 的数据处理与留存条款（服务端处理地区为美国）；订阅税务和各地区销售合规；§11.2 所列中国大陆备案与数据出境要求；服务条款、隐私政策、退款政策文本（同时用于 landing page 与支付平台审核）。
