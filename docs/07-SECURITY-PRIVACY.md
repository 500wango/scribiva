# Scribiva v1.0 — 安全、隐私与权限设计

**性质**：工程安全基线；不是已完成的安全审计或法律合规证明。

## 1. 数据分类与处理

| 数据 | 敏感性 | 处理策略 |
|---|---|---|
| 麦克风音频 | 高 | 仅用户启动录音后采集；默认云端即时处理；不默认永久保存 |
| 转写/修正文本 | 高 | 只为当前插入与失败恢复使用；默认仅本地短期保留；服务端临时结果有 TTL |
| 剪贴板内容 | 高 | 仅完成本次粘贴需要时触及；不作为遥测内容 |
| 用户账号（邮箱）、订阅状态 | 中 | 数据库最小保留；删除/导出遵循披露和合同；魔法链接一次性、短时效 |
| 个人词典 | 中 | 随账户保存在服务端，用户可导出与删除；只用于本人的 ASR 提示与修正保护 |
| 焦点窗口标识 | 低到中 | 只在本机比对，不上传，不读取窗口标题 |
| 用量/错误码/客户端版本 | 低到中 | 仅必要字段；窗口标题、路径、IP 等信息谨慎收集 |
| 系统输入设备权限 | 极高 | 避免键盘监听，禁止默认加入 Linux `input` 组 |

## 2. 威胁模型

| 威胁 | 缓解 |
|---|---|
| 云 ASR/LLM 密钥从桌面包泄漏 | 密钥只保留服务端；桌面持有短期用户凭证 |
| 未授权音频上传 | 默认无常开麦克风；状态显著；拒绝权限不上传 |
| 客户端伪造付费/用量 | 服务端验证 JWT、额度预留、账本与 Stripe webhook |
| 听写文本作为 prompt 注入 | 模型仅做文本编辑；结构占位符；输出验证；不执行语音中的指令 |
| 错贴到聊天窗口、终端 | 焦点快照/校验；不自动发送；不注入高风险上下文 |
| 多驱动重复输入 | `operation_id` 去重；无法确认之前未发送时停止自动回退 |
| 外部剪贴板被覆盖 | 检测剪贴板并发变更；不确定时不恢复；用户可选择禁用粘贴后端 |
| Linux 权限过宽 | 优先 Portal/合成器授权；uinput 最小权限；不以 root 跑主进程 |
| 日志含用户文本/音频 | 结构化 allowlist、脱敏、CI 测试禁止正文进日志 |
| 桌面自动更新被劫持 | 签名制品与更新清单校验、TLS、回滚策略 |
| 恶意音频/超大文件耗尽资源 | 服务端检查真实 MIME、长度、大小、频率及并发 |
| 会话 token 泄漏 | OS 安全凭证存储、短期令牌、刷新令牌撤销 |

## 3. 权限原则

1. 麦克风：首次录音前请求；拒绝时可退出，不假装成功。
2. 快捷键：优先使用官方 Portal/OS 注册 API；不要无理由读取键盘事件流。
3. Linux Wayland：Portal 被拒绝时不绕过用户决定；uinput 后备仅在用户主动选择、明示风险后安装。
4. Windows：不提升为管理员权限来绕过 UIPI；不向安全桌面或密码字段自动注入。
5. Obsidian：不扫描 Vault，不抓取当前笔记正文作为语法修正上下文，不静默修改磁盘笔记文件。

## 4. 第三方服务告知

在用户首次上传前必须显示：供应商名称、为何发送音频/文字、可能的处理地区、供应商留存政策链接、如何取消与删除数据。已确定使用 Groq，服务端部署在美国（ADR-010）：告知中写明处理地区为美国，对中国大陆用户明示数据出境；Groq 的合同与数据留存政策在上线前确认。

禁止在产品中虚假标注“完全离线”“端到端加密、供应商无法访问音频”；云端识别应诚实标注。

## 5. 数据保留与删除的建议基线

- **本地音频**：默认内存缓冲，用完释放；用户明确触发恢复时方可暂存在加密短期文件；默认不跨会话保留。
- **服务端音频**：仅会话内处理或以尽可能短的 TTL 临时储存，并在正常结束后删除。
- **服务端转写**：默认不永久保存，异步结果容忍短 TTL（建议 15 分钟，需安全评审）。
- **本地最近结果**：仅最后一次，默认退出即清；提供“立即清除”。
- **计费元数据**：按账务和适用法规需求设明确期限；隐私政策要说明例外。
- **用户删除**：身份、订阅和用量数据分别定义可删/法定保留流程；删除不得破坏财务记录完整性。

## 6. 最小安全开发流程

- 所有依赖采用 lockfile，CI 执行依赖漏洞扫描、secret scanning、lint/test。
- HTTPS 及后端认证为强制要求；请求大小、速率、token 权限限制必须覆盖全部 API。
- Stripe webhook 需校验签名，存储事件 ID 做去重，必要时核对最新订阅状态。
- 绝不在 Github Actions 日志或客户端异常日志输出用户语音、文本、API keys、refresh tokens。
- Release 安装包/自动更新使用独立签名密钥、最小可访问权限和审核机制。
- 在 Beta 开始前进行威胁建模评审：权限、剪贴板、焦点、网络安全与数据删除。

## 7. 用户可见的安全控制

设置页必须有“当前云端处理状态”“当前使用模型供应商”“清除本地最近结果”“诊断日志开关”“检查 Linux 输入权限”的入口。Linux 系统权限引导必须使用人能理解的语言解释权限范围。

## 8. 安全发布阻断条件

存在未经用户启动的录音、敏感信息默认出现在日志、无需服务端校验即可开启 Pro、Windows 管理员权限滥用、Linux 默认加 `input` 组、**默认**对未验证焦点自动粘贴（用户在设置中看到风险说明后主动开启的除外，ADR-012），这些均为发布阻断。
